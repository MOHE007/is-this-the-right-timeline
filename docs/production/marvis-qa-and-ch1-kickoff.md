# Codex答复Marvis疑问与第一章启动方案

## 结论先行

现在不从改游戏代码开始，而从**第一章制作包**开始。制作包冻结后，再由梁博森做视觉资产、DSH Desktop 接入构建，Marvis 做集中审校，王凯做范围和发布决策。

Demo1 保持原样，作为稳定样片和交互参考；Demo2 是独立的第一章扩展，不覆盖 Demo1。

## 对 Marvis 六组问题的答复

### 1 OAuth 路线

当前路线仍是：**暂不接入知乎 OAuth**。第一章的核心体验不依赖登录，先保证剧情、分支和可玩性。

因此当前按离线模式推进，不需要填写任何平台应用凭证。若后续王凯决定接入官方服务，再单独走平台开发者账号、应用创建、回调地址和服务端凭证配置流程。这个决定属于队长拍板项，不阻塞第一章制作。

### 2 Godot 与内容驱动

Godot 4.x 继续作为冻结的目标引擎。Demo2 的内容采用“**人读 Markdown，运行时消费 JSON**”的分层：

- 剧本、分镜、角色卡、线索卡保留 Markdown，方便人类审阅和 Marvis 批注。
- 运行时内容用 JSON，方便 GDScript 读取、版本比较和分支调试。
- 两天窗口内不先做复杂的自定义 Resource 编辑器；等内容稳定后，再把高频数据迁移为 Typed Resource。

推荐的最小 JSON 结构包括 `id`、`scene`、`speaker`、`text`、`choices`、`conditions`、`effects`、`next` 和 `tags`。GDScript 只负责加载、校验、执行状态变化和切换节点。

`point-n-click` 的思路可以这样复刻：内容作者写 Markdown 和 JSON → 一个轻量校验脚本检查 ID、引用和条件 → Godot ContentLoader 读取 JSON → Dialogue/Choice/Timeline 状态机执行。内容与引擎保持解耦。

### 3 Demo1 到 Demo2 的过渡

不迁移 Demo1 的整套代码。Demo2 只复用经过验证的交互概念和可复用资产：

- 开场文章入口和“问题—回答—行动”的节奏。
- 刘看山三档帮助的交互形态。
- 线索卡、时间线选择、结局页和基础存档字段的命名思路。
- 已确认可用的字体、音效、按钮反馈和水墨 UI 组件。

Demo2 的问答库与 Demo1 分开维护，但共用一个问答接口：`ask(question, context, mode)`。这样 Demo1 不被改动，Demo2 可以拥有更完整的章节上下文和历史资料。

如果最终只发布 Demo2，可复用 Demo1 的标题页、刘看山形象、问答入口、按钮反馈、线索卡框架和音效；驿路线索内容与 Demo1 的具体剧情不直接搬入主线。

### 4 两天协作如何落地

当前第一章制作包的边界是：

- 必做：逐幕剧本、分镜表、角色卡、线索卡、刘看山问答库、分支状态表、JSON 数据草案、实现规格和验收表。
- 暂不做：复杂编辑器、完整 AI 联网服务、第二三章完整内容、自由探索大地图。

梁博森与 Codex 的对接使用“内容 ID + 资源 ID”双向绑定：

- Codex 提供 `scene_id`、`ui_slot`、推荐尺寸、层级、状态和交互说明。
- 梁博森返回同名资源、透明背景/切图信息、尺寸和版本号。
- DSH Desktop 按 `demo2_ch1_类别_内容_v版本号` 归档并接入。

DSH Desktop 在 Godot 下先完成三件事：建立 Demo2 独立项目目录；导入 JSON、图片和音频并保留版本；用 Godot 编辑器或命令行完成 HTML5/桌面测试构建。构建记录必须写入口、版本、运行环境和已知问题。

### 5 刘看山在 Godot 的落地

第一版采用“**本地 JSON 问答库 + 规则匹配 + 可选知乎检索适配器**”：

- 本地库保证离线可玩，字段包含 `question_id`、`keywords`、`context_tags`、`fact`、`background`、`counter_question` 和 `source_status`。
- `current_context` 由章节、幕、场景、已收集线索和当前时间线组成，问答系统只从匹配上下文中取回答。
- 有联网能力时，回答档再调用知乎搜索适配器，取高相关结果；失败就回落本地库，界面不暴露报错。
- 求知度、提问次数、问题类型和是否使用救助写入存档状态，作为分支条件和结局统计，不另建复杂日志系统。

联网增强属于可选服务端能力；普通非登录进程可能没有服务端环境变量，因此脚本和构建流程必须保留本地问答降级路径，不能把联网当成硬依赖。

### 6 发布形态

目标仍是 **HTML5 网页版**，桌面构建用于内部测试和演示兜底。Godot 4 的 Web 导出会生成 HTML、JavaScript、WASM 和资源包，由静态服务器托管；它与 macOS 桌面应用是两套构建目标。

两天内的发布顺序：先完成浏览器可运行版本，再打一个 macOS 测试包。公网托管可选 itch.io、GitHub Pages 或其他静态托管，是否正式上传由王凯在最终验收时决定。

## 现在怎么开始

### 第一个工作块：冻结垂直切片

先只冻结一条 20 至 30 分钟的主路径：现代文章 → 1122 婴儿段 → 刘看山回答岳飞结局 → 1127 后调查 → 1141 召回信息链 → 进入时间线一或时间线二 → 1142 结点 → “直接进入下一章 / 继续游戏” → 辛弃疾入口。

### Codex 先交付的文件

1. `demo2_ch1_script_v01.md`：逐幕剧本与可直接使用的对白。
2. `demo2_ch1_storyboard_v01.md`：每幕镜头、画面、UI 和转场。
3. `demo2_ch1_characters_v01.md`：玩家、刘看山、岳飞、辛弃疾及普通人角色卡。
4. `demo2_ch1_clues_v01.md`：家书、军书、路线图、诏书、证言卡。
5. `demo2_ch1_state_v01.json`：证据、求知、信任、行动倾向、知识债和分支条件。
6. `demo2_ch1_content_v01.json`：运行时对白、选项、条件和效果的 JSON 草案。
7. `demo2_ch1_implementation_v01.md`：给 DSH Desktop 的场景、节点、资源槽位和验收标准。

### 其他人的接手点

- 梁博森：拿分镜和资源槽位定水墨风格、UI 和关键画面。

OAuth 是否为官方人气奖单独追加一条支线流程。这个问题不影响当前第一章开工；在没有明确决定前，按“暂不接入”执行。
